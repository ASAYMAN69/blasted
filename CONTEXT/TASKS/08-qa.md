# TASK 08 — qa (Tests + Verification)

## Role
Write and wire the test suite proving the system works and, crucially, that containment
holds. You are the last line of defense before demo day.

## Write scope (ONLY these)
- `backend/tests/**`

FROZEN (read-only): everything else. Read freely; write only under `backend/tests/`.

## Depends on
- All feature agents' code (engine, sandbox, modes, api).
- Pytest + pytest-asyncio in `backend/pyproject.toml`.

## What to build
1. `backend/tests/conftest.py` — fixtures: tmp task inputs, a real `SandboxManager`
   (requires Docker), monkeypatched LLM client (deterministic fake) for engine tests.
2. Unit tests:
   - Engine state machine transitions and retry-budget logic.
   - Mode registry wiring (all four modes registered).
   - `get_llm_client` selection (Vultr enabled/disabled).
3. Integration tests (real sandbox):
   - Each mode with a small fixture input → PASS + artifacts.
4. Containment negative tests (the stars of the show):
   - Sandbox cannot read host files (e.g., `cat /etc/hostname` → blocked/isolated).
   - Sandbox cannot exfiltrate env vars (`print(open('/proc/1/environ').read())` → fail).
   - Memory-limit and timeout enforcement kill runaway loops.
   - Container is destroyed after task — including on error (check `docker ps -a`).
5. E2E smoke: API submit → poll → artifacts exist (via httpx AsyncClient).

## Acceptance criteria
- `pytest` runs green locally with Docker available.
- Containment negative tests are explicitly labeled (marker `containment`) and all pass.
- You publish a short "containment proof" snippet list for use in the demo video.

## Note
If a test reveals a real bug outside your write scope, report it in
`CONTEXT/STATUS.md` with file/line. Do not fix it yourself.
