The problem

AI can describe work. Can it be trusted to do it?

Real business value requires executing AI-generated code — analyzing data, reconciling invoices, investigating incidents. But running untrusted model output is dangerous. There is no isolation, no verification, and no proof.

Outputs

Models often describe results. Descriptions are not evidence.

Escape

AI code on the host can read secrets, hit the network, or crash the app.

Trust

No verification means no confidence that the result is real or correct.

Proof

Analysts need artifacts — charts, diffs, JSON verdicts — they can audit.

The business case: AI code-execution platforms are a real, growing market. The differentiator is safe, verifiable execution with proof — run untrusted AI code without risk.

The solution

A centralized control layer that plans, executes, and verifies

Users submit a task in plain English — with data files dropped in, up to 20 at once. The agent plans, writes Python, and runs it inside an isolated Docker sandbox on Vultr — then returns the actual outputs: charts, verdicts, diffs, and downloadable artifacts.

01

Real work

Code executes in a real sandbox. Output is returned — not a description of what might have happened.

02

Verifiable

Each step is judged by deterministic rules: exit code, artifacts, structured JSON. Not the model's opinion.

03

Contained

Non-root, read-only filesystem, no network, resource limits, and container destroyed after every task.

Three agents, one engine. A shared agentic loop powers Data Analyst, Invoice Reconciler, and Incident Investigator — pluggable mode registry.

Self-healing. On failure, the previous error is fed back; the agent fixes and re-runs — bounded retries, never an infinite loop.

Production-style. React SPA, FastAPI, SSE live progress, artifact viewer, run history, CI/CD auto-deploy.

The brain

An agent is a loop — not magic

Each task walks the same state machine. Plan and generate are separate LLM calls; verification is deterministic and never delegated to the model.

Failure → bounded retry

If a step fails, the error is fed into the prompt and the agent regenerates — default 3 attempts, then an honest explanation instead of an infinite loop.

Explain + finalize

The LLM summarizes the real output in one terse sentence. Artifacts are copied out of the sandbox, the run card is persisted, and the SSE stream closes.

Sandboxed Agent Studio 07 / 10
How Vultr powers the solution

Vultr is the central control plane

Three Vultr services carry the whole system — from orchestration to inference to execution containment.

01

Cloud Compute VM

2 vCPU / 4 GB Ubuntu VM runs FastAPI, nginx, Docker, and systemd. The web app, engine, and sandbox runtime all live here — the single control point.

02

Serverless Inference

OpenAI-compatible LLM endpoint (api.vultrinference.com/v1, model mimo-v2.6-flash) powers plan generation, code generation, and result summarization.

03

Docker sandboxes

Per-task disposable containers on the VM: non-root, read-only rootfs, no network, resource limits, destroyed after every task. Firewall open to 22 / 80 / 443 only.

Live deployment — http://45.76.2.228, deployed 2026-11-03, CI/CD auto-deploy on merge.

Provider abstraction — LLM client is interface-driven; Vultr is primary, with Ollama / OpenRouter fallback.

Zero secrets in sandbox — credentials stay in .env on the host, never in the container.

Containment negative tests

  • Host filesystem is not mounted
  • Container hostname isolated from host
  • No host env / secrets leak into the sandbox
  • Memory limit kills runaway allocation (exit 137)
  • Timeout kills runaway loops (exit 124)
  • Container destroyed after success / error / timeout / OOM

Verified end-to-end

  • POST task → SSE loop → passed on attempt 1 (~5 s)
  • Artifacts fetchable via API (chart.png → 200) — including text-only step outputs persisted as .json / .txt
  • Multi-file drag & drop verified (up to 20 files per field)
  • Empty-artifact state explains that text/JSON agents produce no binary files — never a misleading "no artifacts yet"
  • CSV input-mapping bug caught and fixed by the suite
